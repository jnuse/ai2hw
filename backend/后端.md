
# 智能职场助手后端实现文档

## 1. 概述

智能职场助手的后端系统主要负责用户管理、智能问答和历史记录管理三大核心功能。该系统基于Flask框架构建RESTful API，使用MySQL存储数据，并通过WebSocket与讯飞星火大模型进行实时通信，提供智能问答服务。

## 2. 技术栈

- **Web框架**: Flask + Flask-CORS
- **数据库**: MySQL (PyMySQL作为连接库)
- **认证**: JWT (JSON Web Token)
- **AI大模型**: 讯飞星火大模型 (X1)
- **通信**: WebSocket (websocket-client库)

## 3. 系统架构

整个后端系统由以下几个核心模块组成：

```
backend/
├── app.py                # 主应用程序入口，定义API路由
├── config.py             # 配置文件，包含数据库、API、星火大模型等配置
├── db_models.py          # 数据库模型类，封装数据库操作
├── spark_api.py          # 星火大模型API封装，处理与AI模型的通信
├── init_db.py            # 数据库初始化脚本
├── reset_db.py           # 数据库重置脚本
├── api_test.py           # API测试脚本
└── requirements.txt      # 依赖列表
```

### 3.1 流程图

用户请求处理流程：
```
客户端 -> Flask API -> 数据库/星火大模型 -> 响应 -> 客户端
```

更详细的流程：
1. 客户端发送HTTP请求到Flask应用
2. JWT中间件验证用户身份
3. 根据请求类型：
   - 用户管理请求：直接与数据库交互
   - 聊天请求：先查询历史记录，然后调用星火大模型，最后保存结果
4. 将处理结果格式化后返回客户端

## 5. API 接口设计

所有API响应遵循统一的格式：
```json
{
  "code": 0,        // 0表示成功，非0表示失败
  "message": "xxx", // 成功或失败的消息
  "data": {}        // 返回的数据，可能为空
}
```

## 6. 核心功能实现

### 6.1 用户认证

用户认证基于JWT实现，具体流程如下：
1. 用户提供用户名和密码登录，或通过微信授权码登录
2. 验证成功后，后端生成包含用户ID和过期时间的JWT Token
3. 返回Token给客户端，客户端存储Token
4. 客户端后续请求在Header中添加`Authorization: Bearer {token}`
5. 后端通过`token_required`装饰器验证Token的有效性

具体实现可参考`app.py`中的`token_required`装饰器和登录API。

### 6.2 星火大模型集成

星火大模型集成是本系统的核心。系统使用WebSocket与讯飞星火X1大模型实时通信，实现了以下功能：
1. 自动鉴权：根据APPID、APIKey和APISecret生成鉴权URL
2. 消息管理：自动格式化消息，添加系统提示词控制输出风格和长度
3. 历史会话：支持上下文关联，保持对话连贯性
4. 流式输出：使用WebSocket接收模型的实时生成内容
5. 思维链过滤：自动过滤模型的思考过程，只返回最终答案

关键类`SparkAPI`封装了与星火大模型的所有交互细节，使主程序可以通过简单的接口调用智能问答功能。

#### 系统提示词设计

### 6.3 历史记录管理

历史记录管理模块负责保存和检索用户的对话历史。主要功能包括：
1. 自动保存：每次聊天自动创建或更新历史记录
2. 标题生成：使用用户的第一个问题作为对话标题
3. 内容格式化：以"用户: xxx\n\n助手: xxx"的格式存储对话内容
4. 上下文关联：根据conversationId关联对话，保持聊天连贯性

## 7. 安全性考虑

### 7.1 密码安全

- 使用SHA-256算法对密码进行哈希存储，不存储明文密码
- 登录时对输入的密码进行相同的哈希处理后与数据库中的哈希值比较

### 7.2 API安全

- 使用JWT Token进行身份验证，控制API访问权限
- Token包含过期时间，默认24小时后自动失效
- 关键操作（如修改个人信息、删除记录）需要验证Token

### 7.3 数据安全

- 使用参数化查询避免SQL注入攻击
- 输入验证和清洗，防止恶意输入
- 按用户隔离数据，确保用户只能访问自己的数据

## 9. 部署说明

### 9.1 环境要求

- Python 3.6+
- MySQL 5.7+
- 网络可访问讯飞星火大模型API

### 9.2 安装依赖

```bash
pip install -r requirements.txt
```

### 9.3 配置修改

部署前需要修改`config.py`中的配置：
1. 数据库配置（DB_CONFIG）：修改为实际的数据库连接信息
2. API配置（API_CONFIG）：根据部署环境修改监听地址和端口
3. 星火大模型配置（SPARK_CONFIG）：填入实际的APPID、APIKey和APISecret
4. 微信小程序配置（WECHAT_CONFIG）：填入小程序的AppID和AppSecret

### 9.4 启动服务

```bash
python app.py
```

也可以使用Gunicorn等WSGI服务器部署：
```bash
gunicorn -w 4 -b 0.0.0.0:5000 app:app
```

### 11.2 数据库初始化SQL

```sql
CREATE TABLE IF NOT EXISTS users (
    id INT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL UNIQUE,
    password VARCHAR(128) NOT NULL,
    openid VARCHAR(64),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE IF NOT EXISTS history_records (
    id INT PRIMARY KEY AUTO_INCREMENT,
    user_id INT NOT NULL,
    title VARCHAR(255) NOT NULL,
    summary TEXT,
    content LONGTEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```
